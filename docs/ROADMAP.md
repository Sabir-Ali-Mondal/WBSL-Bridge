# WBSL Bridge — Website & Extensibility Roadmap

> **Companion to** [`PIPELINE.md`](./PIPELINE.md), which documents how the current
> system actually works and lists the three live bugs.
>
> This file is the **plan**, not a description of what exists. Read `PIPELINE.md` first
> for the facts; read this for what to build next and why.
>
> The guiding constraint: **today there are 97 classes across 3 datasets.
> Tomorrow there may be 30 datasets and 2,000 classes. Nothing here should need to be
> rewritten to accommodate that.**

---

## 1. The problem in one paragraph

The app currently hard-codes the assumption "one dataset, one vocabulary, one model".
Three symptoms prove it: `sign_media.json` has 2 of 97 entries because nobody wired the
auto-population into deployment; models `2`/`3` "detect nothing" because the serving
layer doesn't know they want 32 frames, not 1; and run `2` (97 classes) can never be
rebuilt because the script that produced it is gone. Each of these is the same bug in
different clothing: **the system knows the file names but not the contracts**.

The roadmap below fixes the mental model first, then the code.

---

## 2. Target architecture — the manifest is the source of truth

Introduce **one** declarative file that describes every dataset, every class, and every
model. Everything else — the trainer, the registry, the API, the website — *reads* it
rather than *guessing* from folder names and file mtimes.

```
config/
├── datasets.yaml          # every dataset: id, root, kind, gloss mapping, provenance
├── vocabulary.yaml        # the union: every class ID, its gloss, bengali, category
└── models.yaml            # every run: id, graph, contract, trained-on, metrics
```

### 2.1 `config/datasets.yaml` — one block per dataset

```yaml
datasets:
  - id: isl_static2
    kind: static              # static | video
    root: dataset/Indian Sign Language_Dataset/ISL_STATIC2
    glob: "*.jpg"
    label_from: folder_name
    canonical: true           # preferred source for these classes
    source: "kaggle:ananyaarya22/isl-data"
    license: unknown

  - id: isl_static1
    kind: static
    root: dataset/Indian Sign Language_Dataset/ISL_STATIC1
    glob: "*.jpg"
    canonical: false          # fallback only; isl_static2 wins conflicts

  - id: isl_video
    kind: video
    root: dataset/Indian Sign Language_Dataset/ISL_VIDEO
    glob: "*.mp4"
    seq_len: 32
    gloss_override:
      "Fedup": "FED_UP"       # folder name -> gloss token
```

**Adding a dataset becomes a 6-line YAML append.** No Python edit. That is the whole
point.

### 2.2 `config/vocabulary.yaml` — the union of all classes

```yaml
classes:
  - id: "A"
    gloss: "A"
    bengali: "এ"
    category: alphabet
    static: true              # has a static form
    dynamic: false            # has a video form
  - id: HELLO
    gloss: "HELLO"
    bengali: "হ্যালো"
    category: greeting
    static: false
    dynamic: true
```

This replaces the current implicit union of `sign_classes.json` +
`sign_unified_classes.json` + `sign_video_classes.json`, and it is the file the
**website** renders from. Generated by a tool from `datasets.yaml`, then hand-editable
for Bengali labels.

### 2.3 `config/models.yaml` — the contract, written down

```yaml
runs:
  - id: "1"
    graph: models/onnx_models/1/sign_mlp.onnx
    classes_file: models/onnx_models/1/sign_classes.json
    contract:
      kind: static
      input: [null, 126]      # what the graph ACTUALLY declares
      frames: 1
    trained_on: [isl_static1, isl_static2]
    metrics: { val_acc: 0.999 }

  - id: "3"
    graph: models/onnx_models/3/sign_video_lstm.onnx
    classes_file: models/onnx_models/3/sign_video_classes.json
    contract:
      kind: temporal
      input: [null, 32, 126]
      frames: 32
    trained_on: [isl_video]
```

**Why this matters:** a contract written down in a file can be *validated* against the
probed graph at startup, and a mismatch becomes a loud error instead of a silent
"detects nothing". This is the structural fix for bug B1/B2 in `PIPELINE.md`.

## 3. Pipeline redesign — three decoupled tools

Replace the interactive menu in `train_unified.py` with three composable commands.
Interactive prompts cannot be automated, tested, or called from the website.

```
tools/
├── extract.py    # raw dataset  -> landmark .npy   (per dataset id)
├── train.py      # .npy         -> ONNX run        (configurable vocab)
├── publish.py    # ONNX run     -> registry entry + reference media
└── index.py      # everything   -> dataset/index.jsonl  (exists today)
```

### 3.1 `extract.py`
```
python tools/extract.py --dataset isl_video --force
python tools/extract.py --dataset isl_static2
```
Writes `dataset_train/<dataset_id>/<GLOSS>.npy`. Idempotent, skips existing unless
`--force`, prints ETA. **Critical:** import `extract_two_hands` from `backend/extract.py`
rather than re-declaring it (today the function is duplicated in two files — the exact
drift risk flagged at the end of `PIPELINE.md`).

### 3.2 `train.py`
```
python tools/train.py --datasets isl_video                       # 61-class temporal
python tools/train.py --datasets isl_static2,isl_video           # 97-class unified
python tools/train.py --datasets isl_video --arch mlp --frames 1  # static variant
```
- Vocabulary comes from `vocabulary.yaml` filtered by the requested datasets — **not**
  from `RAW_V.glob()`.
- `--arch {lstm,mlp}`, `--frames N`, `--epochs`, `--seed`, `--out run_id`.
- Emits `models/onnx_models/<run_id>/` **plus** writes the `models.yaml` entry with the
  contract, so the run is self-describing the moment it lands.
- The missing unified trainer from `PIPELINE.md` §6 is simply `--datasets isl_video,isl_static2`.

### 3.3 `publish.py`
```
python tools/publish.py --run 3 --auto-reference-media
```
- Copies one reference sample per class into `backend/media/` and upserts
  `sign_media.json` (this is `build_reference_samples.py`, generalised to read
  `datasets.yaml` instead of a hard-coded `ISL_STATIC2`/`ISL_VIDEO` pair).
- **Runs automatically after `train.py`**, which is what actually fixes the "2 of 97"
  problem — the library should never depend on someone remembering to run a script.

### 3.4 Backend registry rewrite
`_discover_models()` currently infers temporal-ness from substrings in the filename
(`"lstm"`, `"unified"`, `"video"`). Replace with a read of `models.yaml`, falling back to
probing for unregistered runs. Then:
- `_check_model_available()` compares **input rank** to the caller's intent (fixes B2).
- `/api/system/health` reports the model's declared `contract` so the UI can show
  "needs 32-frame clip" **before** the user clicks Predict.
- `active_model.json` is written only on explicit activation, never on passive scan.

## 4. Text → Sign: from lookup table to real playback

Today: Bengali → `gloss_map.json` → gloss list → `sign_media.json` → play each clip in
sequence. That chain is sound; it just needs to be complete and a bit smarter.

### 4.1 Make the chain data-driven
The gloss map should be *generated* from `vocabulary.yaml` (Bengali label → gloss) and
merged with a hand-maintained synonym layer (`backend/data/synonyms.yaml`) for the
phrases people actually type. Today `gloss_map.json` mixes both concerns in one file.
One current bug worth fixing while you are there: the backend splits text on whitespace
*before* matching, so multi-word keys like `"good morning"` can never hit. The
longest-match loop in `main.py:818-838` handles this correctly — keep it, and add a test.

### 4.2 Playback behaviour
- **Static classes** (letters/digits): hold the reference image for ~700 ms.
- **Temporal classes** (word/signs): play the full `.mp4`, no truncation.
- **Unknown tokens** (`[ভালো]`): render a distinct "no sign available" card — never a
  silent gap, and never a fake skeleton.
- **Sequence controls**: speed multiplier, pause between signs, replay.
- **Graceful degradation**: if a class has no reference media, the UI should say so
  explicitly and offer "contribute a recording", linking into the Contribute flow.

### 4.3 The `available_signs` honesty problem
`/api/text-to-sign` returns `available_signs: len(ACTIVE_CLASSES)` — the *model's* class
count. But what a user can actually *see* is the number of entries in `sign_media.json`.
Those two numbers are 97 and 2 today. The UI must show the second number.

## 5. Website plan

### 5.1 Principles
1. **The vocabulary is the product.** Every page should be able to answer "what signs
   exist, and can I see them?" from `vocabulary.yaml` + the reference-media index.
2. **Coverage is visible everywhere.** A sign with no reference media must look
   *different*, not broken.
3. **Nothing is fabricated.** No placeholder skeletons, no invented confidence numbers.
4. **Server-driven.** The frontend should not hard-code model names or class counts.

### 5.2 Page-by-page plan

| Route | Purpose | Key change from today |
|:------|:--------|:----------------------|
| `/` | Landing: what WBSL Bridge is, live health, vocabulary coverage | Show *real* coverage bar (media present / total classes) |
| `/sign-to-text` | Camera → gloss → Bengali → speech | **Show the active model's contract up front.** Disable "Predict" and explain when the model needs a clip; keep "Capture Clip" for temporal runs |
| `/text-to-sign` | Bengali → gloss sequence → sign playback | Rebuild around the generated gloss map + reference index; add unknown-token cards and sequence controls |
| `/dataset` | Browse the vocabulary | Drive from `vocabulary.yaml`; per-class filters for *has media* / *has model class* |
| `/dataset/[signId]` | One sign: reference media, Bengali, category, class index, contributing datasets | New "which datasets contain this class" panel from `index.jsonl` |
| `/contribute` | Record a sign to grow the dataset | Already real; add the "this class has no reference media" entry point |
| `/community/unknown-signs` | Signs the model keeps failing on | Feed from prediction logs (see §5.4) |
| `/admin/models` | Registry + activation | Show declared contract, validate against probe, block rank-mismatched activation |
| `/admin/dataset` | Data inventory | Render `index.jsonl` grouped by kind with counts |
| `/admin/training` | Launch extraction/training | Drive the CLI tools in §3 instead of free-form console |
| `/admin/signs` | Reference media management | Add a "rebuild references for missing classes" bulk action |
| `/admin/evaluation` | Metrics per run | Read `models.yaml` metrics instead of a separate report file |

### 5.3 New API surface needed

```
GET  /api/vocabulary                 -> classes from vocabulary.yaml
GET  /api/coverage                   -> { total, with_media, with_model_class, missing[] }
GET  /api/models/{run}/contract      -> declared vs probed input contract
POST /api/admin/models/{run}/validate-> 200 or a specific mismatch error
POST /api/admin/references/rebuild   -> run publish.py --auto-reference-media for missing
GET  /api/predict/logs               -> recent predictions (for /community/unknown-signs)
```

### 5.4 Prediction logging (small, high value)
Today predictions are never recorded, so "which signs fail most often" is unanswerable.
Append one JSONL line per prediction (`{ts, model, label, confidence, nmm,
hands_detected}`). That single table powers the evaluation page, the unknown-signs
page, and a data-driven answer to "what should the next dataset cover?". It also gives
you the corpus needed to satisfy the "community-driven growth" claim honestly.

## 6. Extensibility contract — how to add a class or a dataset tomorrow

**Add a new video class:**
1. Drop the folder into `ISL_VIDEO/` (or any registered dataset root).
2. `python tools/extract.py --dataset isl_video`
3. `python tools/train.py --datasets isl_video,isl_static2`
4. `publish.py` runs automatically → reference media appears → website updates.
   *Zero code edits.*

**Add an entirely new dataset:**
1. Append a block to `config/datasets.yaml`.
2. `python tools/extract.py --dataset <new_id>`
3. `python tools/train.py --datasets <new_id>,...`
4. Regenerate `vocabulary.yaml`; add Bengali labels for any new classes.
   *Zero code edits in backend or frontend.*

**Swap a model without touching the frontend:** activate it in `/admin/models`; the
contract flows through `/api/system/health` and the UI adapts.

**Definition of "ready":** adding a class must not require editing `train_unified.py`,
`main.py`, or any `.tsx` file. That is the acceptance test for this roadmap.

## 7. Sequenced delivery

### Phase 0 — make it honest (days, not weeks)
- ✅ Fix B3: run `build_reference_samples.py` + `build_index.py` (see `PIPELINE.md` §7).
- Fix B1: `/api/predict/frame` returns a clear `409` naming the required clip length when
  the active model is temporal. Minimum viable, stops the silent failure.
- Fix B2: activation guard checks input **rank**; surface `contract` in health responses.
- Add the coverage counter to the UI so 2/97 is visible instead of invisible.

### Phase 1 — make it declarative
- Introduce `config/datasets.yaml` + `vocabulary.yaml` + `models.yaml`.
- Split `train_unified.py` into `tools/extract.py` / `tools/train.py`.
- Make `publish.py` auto-run after training.
- Recover or re-implement the unified (static+video) trainer; confirm `--datasets
  isl_static2,isl_video` reproduces a 97-class run.

### Phase 2 — make it grow
- Prediction logging + `/api/coverage` + the unknown-signs and evaluation pages.
- Full-motion auto-routing: server-side 32-frame ring buffer so the *single* Predict
  button works for both static and temporal models.
- Contributor attribution, dedup, and train/val/test splits in the manifest.

### Phase 3 — scale
- Multiple registered languages (ISL / WBSL / BSL) with a language switch in the UI.
- Incremental training: add classes without retraining from scratch.
- Automated contract validation in CI — probe every shipped graph and fail the build if
  `models.yaml` disagrees with the artifact.

## 8. Open questions to settle before Phase 1

1. **Is the unified 97-class trainer recoverable?** If not, `train.py` must be written to
   merge static hold-sequences and video sequences into one vocabulary from day one.
2. **Does `ISL_STATIC1` add anything `ISL_STATIC2` doesn't?** (`ISL_STATIC2` has `0`;
   `ISL_STATIC1` does not.) Confirm before declaring one canonical.
3. **Why does `unified_static/` hold 36 files while run `1` has 35 classes, and
   `unified_video/` 62 while run `3` has 61?** Resolve the off-by-one before the next
   training run; a stray class silently shifts every label index.
4. **DPDP Act 2023 posture** — the manifest records `signer_id`; confirm consent capture
   and retention policy before the contributor attribution work in Phase 2.
